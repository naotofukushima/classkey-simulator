# 競馬予想AI (keiba_ai)

「強い / 弱い」の一次元ではなく、**能力指数・ハンデ・展開・馬場・血統・騎手・ローテ**を
分解して積み上げ、最後に**市場オッズとの乖離（期待値）**で買うべき馬を判定するモデル。

勝つために必要なのは的中率ではなく期待値なので、出力の主役は「勝つ馬」ではなく
**「AIの推定勝率 × 実オッズ が 1 を超える馬」** に置いている。

## 使い方

```bash
python3 -m keiba_ai.cli data/races/challenge_cup_2026.json          # 予想
python3 -m keiba_ai.cli data/races/challenge_cup_2026.json --detail # 要素分解つき
python3 -m pytest tests/ -q                                        # テスト
```

依存ライブラリなし（標準ライブラリのみ、Python 3.11+）。

## モデルの構成

| モジュール | 役割 |
|---|---|
| `models.py` | レース条件・出走馬・過去走のデータ構造。クラス格付けと**参照斤量**の定義 |
| `ratings.py` | 1走ごとのパフォーマンス指数 → 直近重み付けで能力指数を推定 |
| `handicap.py` | 負担率(斤量/馬体重)・前走比の斤量増減・休み明け |
| `pace.py` | 逃げ馬の頭数から想定ペースを判定し、脚質 × バイアスを補正 |
| `pedigree.py` | 父・母父のコース適性と、馬場の湿り具合への対応力 |
| `jockey.py` | 騎手・厩舎・追い切り |
| `engine.py` | 全要素を合算 → 勝率・複勝率へ変換 |
| `betting.py` | 期待値で買い目を抽出 |

### 1. 能力指数

```
指数 = クラス基準値 − 着差×8 + (斤量 − そのレースの標準斤量)×1.6 + 頭数補正
```

- **クラス基準値**: G1 106 / G2 100.5 / G3 96 / L 92 / OP 90 / 3勝 85 / 2勝 78 / 1勝 71
  実測の「3勝クラス→重賞」の壁（2000mで約1.0〜1.3秒）に合わせて間隔を設定。
- **参照斤量がこのモデルの肝**。大阪杯や宝塚記念の58kgは古馬牡馬の *定量* であって
  背負わされた重量ではないので加点しない。一方ハンデ戦の58kgはハンデキャッパーが
  課した重量なので加点する。3歳クラシックの57kgも年齢定量なので加点しない。
  ここを一律55kg基準にすると、G1で大敗した馬の指数が不当に跳ね上がる。
- 直近走ほど重い指数減衰（半減期150日）をかけ、上位3走の加重平均と
  ベストパフォーマンスを 72:28 でブレンドする。

### 2. ハンデの読み方

絶対斤量ではなく**負担率 = 斤量 ÷ 馬体重**で見る。
532kgの馬の56kgと、472kgの馬の58kgでは意味が全く違う（10.5% 対 12.3%）。

### 3. 展開

逃げ宣言馬が3頭以上なら自動的にハイペース想定に切り替わり、
逃げ・先行にマイナス、好位差しにプラスを配分する。
当日のトラックバイアス（内外・差し先行）を掛け合わせて最終値を出す。

### 4. 確率への変換（ここを間違えると期待値計算が壊れる）

同じ馬でもパフォーマンスは走るたびにブレる。その標準偏差は2000mで概ね
0.5〜0.6秒 = 4.0〜4.8点。各馬の当日のパフォーマンスをGumbel分布と見なすと
勝率は `softmax(score / T)` になり、`SD = 1.283 × T` の関係から `T ≒ 3.5`。

この温度を適当に決めると、16頭立ての重賞で1番手が50%を超えるような
非現実的な分布になり、期待値がすべて嘘になる。テストで分布のレンジを縛っている。

複勝率はHarvilleモデル（P(1着)+P(2着)+P(3着)）で近似。全馬の複勝率の和が
3.0になることをテストで検証している。

## データについて

`data/races/*.json` に1レース分を格納する。

過去走の着順・着差は、馬柱の自動抽出では**通過順を着順と取り違える誤りが頻発する**ため、
「勝ち馬名(着差)」欄と各レースの確定結果をクロスチェックして確定させている。
（実際に本レースでは、マリアイリダータの3勝クラス「5着」→実際は0.8秒差の**圧勝**、
タガノデュードの大阪杯「13着」→実際はクビ差の**4着**など、複数の重大な誤りを訂正した。）

## 既知の限界 / 今後

- **走破タイム・ラップを使っていない**。着差ベースなので、同じ0.5秒差でも
  高速決着とドスロー決着の区別がつかない。スピード指数（基準タイム＋馬場差）の
  導入が最優先の改善点。
- 係数はレース理論に基づく手動設定で、過去データによる学習・検証をしていない。
  レース結果を蓄積して係数をフィットさせる（もしくは勾配ブースティングに置き換える）のが次段階。
- 血統テーブル・騎手テーブルは主要馬のみ。未登録は中立値で評価される。
- パドック・当日馬体重・直前オッズの変動は未対応。
