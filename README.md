# 競馬予想AI (keiba_ai)

「強い / 弱い」の一次元ではなく、**能力指数・ハンデ・展開・馬場・血統・騎手・ローテ**を
分解して積み上げ、最後に**市場オッズとの乖離（期待値）**で買うべき馬を判定するモデル。

勝つために必要なのは的中率ではなく期待値なので、出力の主役は「勝つ馬」ではなく
**「AIの推定勝率 × 実オッズ が 1 を超える馬」** に置いている。

## 使い方

```bash
python3 -m keiba_ai.cli data/races/challenge_cup_2026.json          # 予想
python3 -m keiba_ai.cli data/races/challenge_cup_2026.json --detail # 要素分解つき
python3 -m pytest tests/ -q                                        # テスト
```

依存ライブラリなし（標準ライブラリのみ、Python 3.11+）。

## モデルの構成

| モジュール | 役割 |
|---|---|
| `models.py` | レース条件・出走馬・過去走のデータ構造。クラス格付けと**参照斤量**の定義 |
| `ratings.py` | 1走ごとのパフォーマンス指数 → 直近重み付けで能力指数を推定 |
| `speed.py` | 走破タイムからの速度指数と、上がり3F×通過順のラップ補正 |
| `lapprofile.py` | コース固有のラップ特性、当日のラップ予測、各馬のラップ形状適性 |
| `handicap.py` | 負担率(斤量/馬体重)・前走比の斤量増減・休み明け |
| `pace.py` | 逃げ馬の頭数から想定ペースを判定し、脚質 × バイアスを補正 |
| `pedigree.py` | 父・母父のコース適性と、馬場の湿り具合への対応力 |
| `jockey.py` | 騎手・厩舎・追い切り |
| `engine.py` | 全要素を合算 → 勝率・複勝率へ変換 |
| `betting.py` | 期待値で買い目を抽出 |

### 1. 能力指数 = 着差指数 × 速度指数 + ラップ補正

```
着差指数 = クラス基準値 − 着差×8 + (斤量 − そのレースの標準斤量)×1.6 + 頭数補正
速度指数 = 96 + tanh飽和( (想定タイム − 走破タイム) × 2000m換算 × 5 )
1走の指数 = 0.65 × 着差指数 + 0.35 × 速度指数 + ラップ補正
```

着差指数はレース内の相対評価なので馬場差には強いが、**そのレース自体の質が分からない**。
速度指数は絶対値を掴めるが、日々の馬場差というノイズを持つ。だから両方を混ぜる。

- **クラス基準値**: G1 106 / G2 100.5 / G3 96 / L 92 / OP 90 / 3勝 85 / 2勝 78 / 1勝 71
  実測の「3勝クラス→重賞」の壁（2000mで約1.0〜1.3秒）に合わせて間隔を設定。
- **参照斤量がこのモデルの肝**。大阪杯や宝塚記念の58kgは古馬牡馬の *定量* であって
  背負わされた重量ではないので加点しない。一方ハンデ戦の58kgはハンデキャッパーが
  課した重量なので加点する。3歳クラシックの57kgも年齢定量なので加点しない。
  ここを一律55kg基準にすると、G1で大敗した馬の指数が不当に跳ね上がる。
- 直近走ほど重い指数減衰（半減期150日）をかけ、上位3走の加重平均と
  ベストパフォーマンスを 72:28 でブレンドする。

#### 速度指数（走破タイム軸）

`想定タイム = 会場別の基準タイム + クラス補正 + 馬場状態補正`

- **基準タイム**は教科書的な表ではなく、**出走各馬が2025-26年に実際に走ったレースの
  勝ちタイムから逆算**して置いている（例: 小倉芝2000 は小倉記念1:58.0 / 関門橋S 2:00.3 /
  小倉日経OP 1:59.4 から 118.3秒）。出典が同一シーズンなので現在の馬場に近い。
- 距離は 2000m 換算に正規化する。
- 絶対タイムは馬場差ノイズを含むので、着差より換算率を抑え（1秒=5点）、
  **tanh で滑らかに飽和**させる。ハードな打ち切りにすると
  「コースレコード」と「条件戦の好時計」が同点になり順序が壊れる。

この軸を入れて初めて拾えたのが**マリアイリダータの前走**で、
着差ベースでは「3勝クラスを勝っただけ」だが、実際は**福島芝2000のコースレコード1:56.7**
（2013年ダイワファルコンの記録を0.6秒更新）。速度指数は全馬中最高の103.8になる。

#### ラップ補正（上がり3F × 通過順）

最後方から上がり最速を出すのは展開利で起こりうるが、前めの位置で速い上がりを使うのは
純粋に強い。そこで

```
補正 = tanh飽和( (基準上がり − 自身の上がり3F) × 4 × (0.45 + 0.55 × 前にいた度合い) )
```

通過順は「先頭=0, 最後方=1」に正規化してから使う（少頭数で前めに見えすぎるのを防ぐ）。
基準上がりの**クラス補正は符号に注意**で、下級条件戦はペースが緩みやすく
上がりはむしろ速く出るので、G1をプラス・1勝クラスをマイナスに置いている。

### 2. ハンデの読み方

絶対斤量ではなく**負担率 = 斤量 ÷ 馬体重**で見る。
532kgの馬の56kgと、472kgの馬の58kgでは意味が全く違う（10.5% 対 12.3%）。

### 3. 展開 ―― ラップを予測してから脚質を評価する

「速い/遅い」より **どういうラップを刻むか** の方が着順を決める。
同じ1:58.0でも、前半58.4−後半59.6の消耗戦と、60.0−58.0の瞬発戦では
求められる資質が別物になる。そこで3段階に分ける。

#### (a) コースの par ラップ

コースごとに「その条件で標準的に刻まれる200mごとの区間」を持つ。
阪神芝2000m内回りの par は教科書値ではなく、
**2025年チャレンジカップ（同一コース・同一開催時期）の実ラップ**
`12.6-11.5-11.9-11.3-11.1-11.8-12.1-12.1-11.7-11.9 (1:58.0)` を
基準タイム117.8秒に合わせたもの。

このコースの形は独特で、

```
12.6   11.5   11.9   11.3   11.1 │ 11.8   12.1   12.0   11.6   11.9
発走   1角へ   1-2角  向正面(下り)   │        3角    4角    直線    坂
       └─ 位置取り ─┘  └─ ここが速い ─┘  └ 中弛み ┘ └ 二段目の加速 ┘
```

つまり **「速い向正面 → 3-4角の緩み → 直線での二段加速 → 坂」の2段ギアチェンジ型**。
単発の瞬発力より、緩んだところで置かれずに4角までポジションを取れる機動力と、
坂を踏ん張る持続力が要る。レースの上がり3Fは35秒台が標準で、
極端な上がり勝負にはなりにくい。

**par の時点で前半1000mの方が1.0秒速い**点が重要で、
ペース判定を絶対値でやるとこのコースは常に「ハイペース」になってしまう。
判定は必ず par との差で行う。

#### (b) 当日のラップ予測

par を出発点に、以下で200mごとに補正する。

- 逃げ・先行の頭数 → テンの区間を速く、その反動で終い3Fを掛かる方向へ
- 開催週・クッション値 → 全体の時計
- 含水率 → 坂を含む終い2Fの脚の上がり方
- 頭数 → 枠取り争いの激しさ

#### (c) 各馬のラップ形状適性

過去走ごとに `形状 = 上がり3F − 走破タイム×(600/距離)` を出す。
均等ペースならこの値は0で、正なら「前半が速い消耗戦を走った」ことになる。
この形状と、その走のパフォーマンス指数との相関を、**その馬の中で標準化**して取る。
標準化するので、差し馬の上がりが構造的に速いといった脚質由来の定常バイアスは消え、
「相対的に前傾のレースで走れているか」だけが残る。サンプルが4-5走と少ないので
`n/(n+3)` で0方向に縮小し、上限±1.2点で抑える。

あわせて **4角での平均位置** も見る。内回り2000mは4角で後ろだと物理的に届かない。

#### (d) 展開シナリオ感度

ハナ争いの出方は当日の駆け引き次第なので、`--scenarios` で
「単騎逃げ」「超ハイペース」など展開が振れた場合の勝率変化を出す。
結論が展開に過敏なら、その予想は使えない。

### 4. 確率への変換（ここを間違えると期待値計算が壊れる）

同じ馬でもパフォーマンスは走るたびにブレる。その標準偏差は2000mで概ね
0.5〜0.6秒 = 4.0〜4.8点。各馬の当日のパフォーマンスをGumbel分布と見なすと
勝率は `softmax(score / T)` になり、`SD = 1.283 × T` の関係から `T ≒ 3.5`。

この温度を適当に決めると、16頭立ての重賞で1番手が50%を超えるような
非現実的な分布になり、期待値がすべて嘘になる。テストで分布のレンジを縛っている。

複勝率はHarvilleモデル（P(1着)+P(2着)+P(3着)）で近似。全馬の複勝率の和が
3.0になることをテストで検証している。

## データについて

`data/races/*.json` に1レース分を格納する。

過去走の着順・着差は、馬柱の自動抽出では**通過順を着順と取り違える誤りが頻発する**ため、
「勝ち馬名(着差)」欄と各レースの確定結果をクロスチェックして確定させている。
（実際に本レースでは、マリアイリダータの3勝クラス「5着」→実際は0.8秒差の**圧勝**、
タガノデュードの大阪杯「13着」→実際はクビ差の**4着**など、複数の重大な誤りを訂正した。）

## 既知の限界 / 今後

- **日次の馬場差（トラックバリアント）を持っていない**。速度指数の基準タイムは
  シーズン内の複数レースから逆算しているが、開催日ごとの高速/時計のかかる差までは
  補正できず、±0.5秒程度の誤差が残る。JRAが公開する含水率・クッション値の日次データを
  取り込んで、その日の全レースの勝ちタイムからバリアントを推定するのが次の一手。
- **ラップは上がり3Fと通過順までしか使えていない**。本来はレースの前後半バランス
  （前傾/後傾ラップ）まで見たいが、全走のラップ table が取得できていない。
- 走破タイムは全72走中62走ぶんしか揃っていない。欠測走は着差指数のみで評価される。
- 係数はレース理論に基づく手動設定で、過去データによる学習・検証をしていない。
  レース結果を蓄積して係数をフィットさせる（もしくは勾配ブースティングに置き換える）のが次段階。
- 血統テーブル・騎手テーブルは主要馬のみ。未登録は中立値で評価される。
- パドック・当日馬体重・直前オッズの変動は未対応。
